# 버킷 업데이트·보호설정 콘텐츠 배치 개선 검증

2026-11-02 Asia/Seoul. Epic #1527 / PR #1541의 같은 `dhslove/epic-1527-buckets` 브랜치에 추가 요청을 구현했다. 31 GFS2·32 RBD Mold의 실제 UI/API/DB와 32번 Glue를 사용했다.

## 문제와 변경

버킷 업데이트 창이 보호설정 탭 전체를 위에 다시 렌더링해 편집 필드와 요청값·실제값·지원 상태가 중복됐다. 상단 정보 리본3개와 비교 표 때문에 일반 상태에서도 입력 콘텐츠 높이가1315px였다. 보호설정 탭도 정보 리본2개 뒤에 작업 버튼이 있었고 콘텐츠 높이는804px였다.

- 보호설정 탭의 첫 영역은 확인·복구·실제값 반영 작업 버튼이다. 요청값/실제값/지원 여부를 한 표로 통합하고 검증 상태·조회 시각·작업ID는 표 아래 일반 콘텐츠로 표시한다. 동일한 최근 조회/정상 확인 시각은 한 번만 표시한다.
- 업데이트 창은 할당량·정책·보호 옵션 편집 필드를 먼저 보여준다. 전체 보호 비교 표와 지원 상태 리본은 제거했다. 객체 잠금은 읽기 전용 실제 상태로 보여주며 요청값과 실제값이 다를 때만 관련 필드에 차이를 덧붙인다.
- 용량 참고 정보는 할당량 필드 아래에 배치하고 상세 검증 기준/시각은 펼침 영역에 모았다. 보호 기능 제약·HTTP 암호화 조건·객체 잠금 생성 제약·검증 범위는 하단의 보호 설정 안내에서 읽을 수 있다. 단순 안내용 상단 리본은 없다.
- 실제 오류 메시지는 해당 콘텐츠에 유지한다. 진행 중 작업의 편집 차단·복구·확인창·재시도와 기존 POST/API 계약을 유지한다. 업데이트의 복구/검증 버튼과 취소·확인은 disabled 폼 밖에 두고 제출 버튼은 pending 상태에서 명시적으로 비활성화했다.

## 실제 UI 검증

동일1280×900px에서 보호설정 콘텐츠 높이는804→391.69px, 업데이트 콘텐츠는1315→381.03px로 줄었다. 업데이트 첫 필드는 Y≈1091px에서 Y≈287px로 이동했다.

31/32 × light/dark × 360/768/1280px × 보호설정/업데이트 **24뷰**를 실제 UI로 검사했다. 각 뷰의 실제 viewport는 JSON과 원본 JPEG 디코딩 크기로 대조했다. 단순 안내 리본0개, 탭 버튼이 표보다 앞에 배치됨, 업데이트 첫 콘텐츠는 편집 폼이며 중복 비교 표0개다. 정상 상태 본문 텍스트 최소 대비는 **5.19:1**이다. 페이지/폼 가로 넘침0, 모바일은 단일 열이며 하단 확인·취소에 접근할 수 있다. 일반 작업 버튼은 VM 메뉴와 같은14px 글꼴/32px 높이/4px 모서리를 사용한다. 보호 비교 표는 좁은 화면에서 내부 가로 스크롤을 제공한다.

초기 360px 검사에서 전역 폼 스타일이 라벨/입력란을 가로로 배치해 넘침을 일으켰다. 업데이트 폼 내부의 form-item을 block/100% 폭으로 지정하고 최종 앱에서 위24뷰를 다시 통과했다. 접힌 보호 안내·할당량 기준은 키보드로 펼쳐 읽고 다시 접을 수 있다. 높이/첫 입력 좌표 등 원본 수치는 증거 JSON을 따른다.

전용 빈 QA 버킷에서 양쪽 UI의 잘못된 할당량0 입력을 필드 오류로 차단하고 정상2GiB로 저장했다. Mold API/DB quota2, Glue quota2147483648B, Private 정책과 기존 보호 설정 일치를 확인했다. 최종 앱에서도 입력 검증·저장 및 취소를 확인했다.

각 QA 저장소만 실제로 연결 불가 포트에 잠시 지정해 보호설정 재조회 실패를 만들었다. 오류는 작업 버튼 아래 표시됐고 상태는 Unknown으로 구분됐다. 저장소의 원래 URL을 복원한 뒤 UI 재시도로 Verified/오류 해제를 확인했다. 동일 컨트롤러를 사용하는 업데이트 창에서도 최종 앱의 실패/복구 표시를 검사했다. 운영/확인용 저장소·인증 키는 변경하지 않았다. 실제 장애 복구 검사와 기존95개 단위 회귀는 구분한다.

## 정리·보존

추가한 QA 버킷/저장소/계정/credential 활성 행과 RGW tenant는 모두 정리했다. pending quota operation/예약 바이트/임시 reservation0, 수동 카운터 수정0. 최종31은 버킷/저장소0/0,32는 원래 확인용1/1이며 Root bucket/object_storage도0/0,1/1073741824B다. 각 컴퓨트 호스트3대Up, Mold active, /client/200, Glue HEALTH_OK/RGW3 running이다.

별도 확인용 `qa-bkt-1540-32-files`는 원래12개 raw S3 객체의 이름/크기/원본 바이트 SHA256, 기존 키 집합과 credential revision, 실제 보호 설정·계정 상세를 보존했다. 원래 확인용 버킷은 읽기/대화상자 취소만 수행했다. 기존 Windows/WSL FT 작업트리는 수정하지 않았다. 실제 키·제공 암호는 공개 소스/증거에 포함하지 않았다.
