# #1569 역할별 UI 생성·NIC 연결과 조건부 회귀 (2026-11-08)

31 GFS2·32 Glue RBD에서 **Isolated·L2·Shared × Admin/owner/member/DomainAdmin의 UI 생성 24건과 UI NIC 연결 24건**을 완료했다. 네트워크의 프로젝트 소유권, 비동기 작업 완료·실제 호출 사용자, 작업 결과 NIC와 최종 API·호스트 인터페이스를 대조했다. 제한 역할의 직접 API 거부 48건, 프로젝트/VM 접근 범위 조회 32건도 기대와 일치한다.

권한 검증은 통과했으나 **생성 대화상자의 소유 프로젝트 표시 부족과 390px 다크모드 NIC 표의 고정 열 제목 겹침**을 추가 발견했다. 모바일을 일괄 통과로 기록하지 않는다. #1569·Epic #1554·Draft PR #1577은 Open으로 유지한다.

## 조건부 UI/API

각 유형의 상세 탭과 VNF 기기 탭을 양쪽에서 열었다. Isolated는 상세/송신 규칙/Public IP/가상 라우터/VNF/이벤트/코멘트, L2는 상세/VNF/이벤트/코멘트, Shared는 상세/IP/가상 라우터/VNF/게스트 IP 범위/이벤트/코멘트를 확인했다. 미지원 Tungsten 정책 탭은 표시되지 않았다.

Admin·owner·member·readonly·DomainAdmin × 세 유형 × 두 곳의 **VNF 연관 조회 30건은 정상 빈 목록**이다. 관리자 Tungsten 제공자 조회는 Zone 지정/미지정 × 두 곳의 4건 모두 정상 빈 목록이며 #1591 수정이 유지된다. 양쪽 기존 Skudonet 7.2.1 VNF 템플릿은 isready=true다. **이번에는 VNF를 배포하지 않았고 연관 장비의 기동·NIC·실제 트래픽을 검증한 것이 아니다.**

## VM UI 표준·이동·반응형·다크모드

**이번 변경은 검증 문서·증적이며 제품 UI/서버 소스와 스타일 변경은 없다.** 이미 배포된 화면을 VM 메뉴와 비교했다.

- 목록→상세→NIC 탭, breadcrumb의 목록 복귀와 재진입, 네트워크 상세/탭을 확인했다. NIC 탭은 텍스트 기본 작업 버튼 뒤에 갱신 버튼을 두는 기존 VM 툴바를 사용한다.
- 양쪽 기본 보기↔QA 프로젝트 전환은 대시보드로 이동하며 이전 VM/NIC 화면이 제거됐다. QA로 돌아와 대상 VM에 재진입했다. 최종 선택은 QA 프로젝트다. 프로젝트 검색은 원격 로딩 결과가 나온 뒤 선택된 표시를 확인했다.
- 1280×900·768×1024·390×844에서 라이트/다크 12개 캡처를 보존했다. 실제 viewport와 JPEG 치수를 대조했고 테마는 DOM dark-mode 및 실제 배경색으로 확인했다. 390px 표는 수평 스크롤을 사용한다.
- 31 라이트·32 다크의 390px 기존 네트워크 연결 대화상자는 VM/Zone/프로젝트 문맥과 세로 입력·취소/연결 버튼의 가독성을 확인했다. 열기·읽기·취소만 수행했다.
- **390px 다크 NIC 표에서 고정 작업 열 배경 뒤의 장치 ID 제목이 비쳐 겹친다. 양쪽 원본 캡처로 확인한 실패이며 후속 수정 대상이다.** 라이트 캡처는 같은 겹침이 보이지 않는다. 스크롤 위치에 따라 sticky breadcrumb 아래의 툴바 일부가 가려진 프레임도 있으며, 이를 별도의 기능 장애로 단정하지 않았다.
- 최종 뷰포트 오버라이드를 해제하고 31 라이트·32 다크, root 관리자, QA 프로젝트의 새 VM 4 NIC 화면을 남겼다.

## 자원·런타임 보존

신규 확인 자원은 **네트워크 24개와 VM 2개**다. 역할을 바꿀 때 새 VM의 보조 NIC만 연결 해제해 다음 조합을 검사했고, 생성한 네트워크는 모두 남겼다. 최종 새 VM은 기본 Shared NIC와 DomainAdmin이 연결한 Isolated/L2/Shared NIC, 총 4개다. 실제 호스트 libvirt의 MAC 4개가 API와 일치한다. 기존 검증 VM의 원래 NIC 8개·주소/MAC/default·호스트는 그대로다.

원래 프로젝트에서 보이던 네트워크 27/28개와 멤버/역할·다른 제한은 유지했다. 새 12개를 보관해 현재 프로젝트 보기 39/40개다. **QA 프로젝트 네트워크 한도만 30→50으로 늘렸고, 자원 확인이 끝날 때까지 유지한다.** 기존 LB 각 5개 Active·인증서·FW/PF·공유 권한 2행과 운영 자원 지문은 변하지 않았다.

활성 관리 JAR SHA256 `2faddb218741a22b1e83ff89337adb73e0a981d525c2bdc32c313b7bb33b8592`, 정적 UI 662개 해시, FTCTL/네트워크 표식·WEB-INF·HTTP 200·mold active를 재확인했다. 최근 관리 로그 15,000행에 linkage 오류가 없다. 제품 소스 변경·재배포·모듈 빌드·전체 Cloud 빌드·Actions 실행은 이번에 없었다.

## 남은 항목과 후속 순서

1. 모바일 다크 NIC 표 겹침을 수정하고 양쪽 390/768/1280px, 수평 스크롤·작업 버튼·기본 NIC 보호를 재검증한다.
2. 세 유형 생성 대화상자의 실제 소유 계정/프로젝트 문맥을 VM 연결 대화상자 표준으로 명시한다. 필터와 쓰기 소유 범위를 분리해 설명한다.
3. #1569에서 준비된 Skudonet의 실제 UI 배포·연관 네트워크/기동/NIC 표시와 실패 복구를 검증한다. L2 ConfigDrive, PVLAN 격리, VPC ACL/라우터 및 아직 실행하지 않은 역할·서비스 변형을 이어간다.
4. LB health/AutoScale·TLS/인증서·제공자별 미실행 조합을 검증한다. 사용자 지시에 따라 백엔드 부하분산 트래픽 자체를 필수로 확대하지 않는다. 실제 통신이 필요한 시험은 VLAN 스위치 미설정을 고려해 라우터와 같은 호스트에 배치한다.
5. IPv6/DualStack·BGP/Routed·Tungsten 데이터 평면은 별도 주소/피어/제공자 환경이 준비된 뒤 수행한다. #1586 RBD 물리 잔여 정리는 별도 후속이다.

Epic 63개 행은 **실패 1·부분 48·미실행 5·환경 차단 6·적용 제외 3·전체 행 성공 0**으로 갱신했다. C06의 모바일 실패를 반영했으며 권한 48개 UI 작업의 성공을 다른 미실행 조건까지 확대하지 않는다. [행별 커버리지](../guest-network-1569-integrated/coverage.ko.md).
