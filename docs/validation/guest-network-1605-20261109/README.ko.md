# #1605 공통 breadcrumb 폭·스크롤 및 IP 탭 업데이트 버튼

상위 Epic #1554 · 통합 회귀 #1569 · 유지 브랜치 `dhslove/epic-1554-guest-networks` · Draft PR #1577.

## 변경 이유와 설계

공통 워크벤치는 `.layout-content` 내부에서 본문을 스크롤하지만 기존 breadcrumb의 AntAffix는 window 스크롤을 기준으로 고정 상태와 픽셀 폭을 캐시했다. 31번에서 VM의 NIC 링크로 Shared 네트워크에 진입한 후 본문 스크롤 시 breadcrumb가 화면 밖으로 사라지고, 같은 URL을 새로고침하면 고정되는 차이를 실제로 확인했다. 이전 #1569 증적에는 32번 390→1280px 확대 시 356px 폭이 남는 실패가 있다.

- 모든 breadcrumb 사용 구현 12곳을 점검했다. 공통 AutogenView와 별도 이벤트·도메인·인프라·설정·관리 도구·DR 화면의 breadcrumb를 동일한 `content-breadcrumb` 스크롤 고정 규칙으로 통일했다.
- 실제 스크롤 컨테이너의 상단 `position: sticky; top: 0`와 일반 레이아웃 폭을 사용한다. window 기준 픽셀 폭·placeholder·화면 유형별 재마운트와 ResizeObserver를 제거했다. 진입·새로고침·리사이즈·메뉴·배너 변화가 동일한 레이아웃 계산을 따른다.
- 카드의 음수 상단·좌우 여백을 공통 breadcrumb 영역에서 정규화해 잘림을 막았다. 기존 VM 공통 카드·breadcrumb·작업 드롭다운·버튼 순서·테마 토큰을 사용한다.
- Shared의 **IP 주소 탭**과 **게스트 IP 주소 범위 탭** 업데이트 버튼을 VM NIC 탭과 같은 기본 버튼의 **reload 아이콘 + 업데이트 텍스트**로 통일했다. 기존 로딩·권한·편집 중 비활성화·데이터 보존 동작과 조회 API를 유지한다.
- API·서버·보안 정책 변경은 없다. 안내 배너와 VNF 배포 측면 요약처럼 breadcrumb가 아닌 Affix는 그대로 사용한다.

## 검증과 배포

최종 UI 검증 결과와 캡처는 [증적](evidence/ui-results.json), [캡처 목록](capture-matrix.ko.md)에 기록한다. 최초 진입과 새로고침의 스크롤 결과, 고정 폭과 부모 폭, 실제 viewport, 테마, 페이지 가로 overflow를 각각 측정한다.

UI의 로컬 lint, 관련 단위 회귀 **6개 suite / 94개 테스트**, 최종 production UI 빌드가 통과했다. 전체 Cloud 빌드나 서버 모듈 빌드는 실행하지 않았다. 구현 커밋은 `b2491ac151f16421ea9e2f65bacba6358655a226`이며 검증에 사용한 WSL 소스와 대조한다.

31·32의 활성 경로 `/usr/share/cloudstack-management/webapp`에 동일한 정적 파일 **662개 / 30,023,472 bytes**를 배포했다. 배포 전 백업을 보관하고 WEB-INF·META-INF·런타임 설정·관리 JAR·프로세스 유지와 /client/ HTTP 200, 파일별 SHA-256 일치를 확인했다. index SHA-256은 `bf5ccba0b68dda3e804eebd621b66a66d0797465b126cd3075bcc0fa4ab7bc81`이다.

| 검증 | 결과와 범위 |
|---|---|
| breadcrumb 동적 폭 | VM·Shared 네트워크 상세 × 31·32 × 라이트·다크 × 390→768→1280→768→390, **40개 케이스 통과** |
| 공통 화면 진입·새로고침 | 31은 12개 경로, 32는 10개 경로를 각각 진입/새로고침으로 확인. 스크롤 가능한 화면에서 본문 상단 고정 위치가 일치하고, 내용이 짧은 화면은 폭·배치를 확인 |
| IP 탭 업데이트 | 2개 탭 × 2개 클러스터 × 2개 테마 × 3개 폭, **24개 케이스 통과**. 표시되는 버튼만 판정하고 비활성 탭의 숨겨진 DOM은 제외 |
| UI에서 발생한 조회 API | 31·32 모두 listPublicIpAddresses **200 / 9개**, listVlanIpRanges **200 / 1개** |
| 프로젝트 전환 | 기본 보기와 시험 프로젝트를 실제 선택하고, 확정된 프로젝트 표시와 VM 재진입·NIC 링크 이동을 확인. 중간 전환/선택 미완료 캡처는 진단 기록으로 구분 |
| 메뉴·배너 변화 | 31·32 메뉴 접힘/펼침 시 폭 갱신. 반응형 경보 배너 높이 변화 시 실제 본문 상단 위치에 breadcrumb 유지 |
| VM 공통 대화상자 | 31 라이트/32 다크 × 390/1280px **4개 케이스**. 기존 네트워크 연결 양식·푸터·취소 확인, 연결 제출 없음 |
| 실제 치수 | **137개 DOM 기록 중 breadcrumb가 있는 131개** 모두 고정 위치·폭 검사 통과. 페이지 가로 overflow 없음 |

공통 화면 경로는 VM·네트워크 목록, 인프라 요약, CPU 소켓, DB/Usage 서버, 전역 설정, 도메인, 사용량, 인스턴스 관리, 데이터 볼륨 가져오기, DR 사이트·DR 계획이다. 32번에는 현재 DR 사이트/계획 UI 메뉴가 제공되지 않아 두 경로는 실환경 적용 제외로 기록했다. legacy EventDownload는 라우트 참조가 없어 소스 전환·컴파일만 확인했다. 모든 메뉴의 모든 개별 탭을 새로 전수 실행했다는 뜻은 아니다.

원본 JPEG 85장을 보관했다. viewport를 기록한 81장 중 **77장은 실제 viewport와 디코딩 치수가 일치**한다. 반환 이미지가 1280×641로 내려온 4장은 치수 불일치로 반응형 캡처 근거에서 제외했다. 해당 UI의 DOM 치수 기록과 최종 원래 창 크기의 확인 화면은 별도로 유지한다. [이미지 무결성](evidence/image-integrity.json)과 [검증 집계](evidence/validation-summary.json)에 원본/진단/제외 범위를 명시했다.

초기 브라우저 제어 도중 응답 시간 초과로 연결을 복구했다. 시험 자원은 변경하지 않았으며 저장된 증적을 이어 썼다. 도메인 화면의 로딩 중 입력 응답 지연은 완료 후 실제 스크롤 위치로 재확인했다. 자동화 도구의 대상·치수·응답 지연은 제품 기능 실패로 집계하지 않았다.

GitHub Actions의 전체 CI 성공을 주장하지 않는다. 로컬 lint·94개 단위 회귀·UI 빌드와 실제 배포·UI·조회 API 검증 결과를 구분한다. 기존 PR의 License Check 실패는 이전 보고서의 CI 범위 기록을 따른다.

## 확인용 자원과 후속

[확인용 자원](resources.ko.md)은 이전 #1569 자원을 유지한다. 이 작업에서는 VM·네트워크를 생성·삭제하거나 NIC·라우터·권한을 변경하지 않는다.

이번 #1605 구현·검증 범위를 완료했다. #1569와 Epic/Draft PR은 남은 통합 회귀를 위해 유지한다. 후속은 서비스 연결 VPC 삭제 영향·남은 Shared 공유 범위/역할 → VPN/LB UI·API/health/AutoScale 조건 → 환경이 준비된 PVLAN/IPv6/BGP/외부 DNS 순이다. 사용자가 제외한 백엔드 부하 분산 측정은 포함하지 않는다.

최종 확인 화면은 31번 IP 주소 탭(라이트), 32번 게스트 IP 주소 범위 탭(다크)이다. 임시 viewport는 해제하고 대화상자는 닫았다. 기존 시험 네트워크·VM·NIC·라우터와 주소 범위는 유지했다.
