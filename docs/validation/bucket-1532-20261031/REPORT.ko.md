# #1532 빈 버킷 삭제·버전 관리·명시적 정리 검증

검증 시작: 2026-10-31 · 완료: 2026-11-01T00:07:37+09:00

같은 `dhslove/epic-1527-buckets` 브랜치에서 일반 삭제의 관리자 강제 제거를 없애고, 버전별 조회/복구/삭제와 별도 영속 비동기 정리를 구현했다. 31번 GFS2·32번 RBD 관리 서버에 반영해 UI, Cloud API/DB, 실제 32번 Glue S3를 대조했다. 두 클러스터의 버킷 데이터는 모두 Glue에 저장되며 GFS2/RBD에 직접 저장한 시험은 아니다.

## 개선 결과

- `deleteBucket`은 현재 객체·이전 버전·삭제 마커가 없는 경우에만 성공한다. 조회 실패는 빈 상태가 아니다. 사전 조회 이후 업로드가 생겨도 최종 비강제 S3 DeleteBucket이 거부한다. RGW 관리자 purge로 폴백하지 않는다.
- 삭제 영향 조회, 버전 페이지/연속 마커, 정확한 key/version 삭제, 이전 버전 복사 복구와 삭제 마커 제거를 제공한다. 한글·콜론이 포함된 객체 키의 실제 GET/버전 ID를 대조했다.
- 별도 `purgeBucket`은 정확한 이름·버전 포함·되돌릴 수 없음 동의와 클라이언트 UUID를 사용한다. 영속 원장에 1000개 배치, 확인된 개수, 실패 항목과 진행 불확실성을 저장한다. 완료 후에도 같은 UUID의 조회/재전송은 중복 차감을 만들지 않는다.
- 부분 실패/응답 유실/재시작/최종 DB 실패에서는 메타데이터·소유권·할당량을 유지한다. 객체 잠금 상태 미확인 또는 객체 잠금 활성화 버킷의 버전 변경·purge는 차단하며 보존/Legal Hold를 우회하지 않는다.
- 6개 민감 API의 POST·no-store와 소유자 허용/다른 계정 거부를 확인했다. 진행 중 purge와 일반 삭제·할당량·키 회전·버전 변경·다른 정리 UUID의 충돌도 양쪽에서 차단했다.
- UI의 일반 삭제와 명시적 정리 확인/진행·재시도 화면을 분리했다. 버전 탭 및 명시적 이름의 그룹 삭제 버튼을 제공한다. 라이트 hover 대비와 미등록 성공 알림 번역 키는 실측 후 수정했다.

## 실제 기능 검증

| 범위 | 실측 결과 |
|---|---|
| 빈 버킷 일반 삭제 | 31/32 UI 성공, S3 404와 Cloud 활성 목록 0 확인 |

| 조회 오류·권한 | 31 버전 조회 503, 32 S3 ListBucketVersions 권한 거부에서 삭제 차단. 권한 복구 후 조회 정상 |

| 1000개 초과·부분 실패 | 31 UI에서 1105개 정리, 특정 키 거부로 999개 확인/106개 잔존·할당량 유지. 동일 UUID UI 재시도로 1105개 완료 |
| 실행 중 재시작 | 32 UI 정리를 1000개 체크포인트에서 서버 중지. 남은 105개·DB/할당량 확인 후 재시작, 같은 UUID가 자동 재개해 1105개 완료 |
| 응답 유실 | 31 DeleteObjects 실제 실행 후 응답을 버림. NeedsReconcile·진행 불확실 표시, UI 같은 UUID 재시도로 완료. 확인되지 않은 8개를 확인 개수에 임의로 더하지 않음 |

| 그룹 삭제 | 양쪽 실제 UI에서 빈/비어 있지 않은 버킷 혼합 선택. 빈 대상만 성공, 나머지는 대상별 실패 및 S3 내용 유지 |
| 최종 UI 복구 | 최종 배포본에서 양쪽 권한 거부 시험 버킷의 오류 항목·확인 동의·같은 UUID 재시도를 검증 |

범위별 JSON과 실제 화면은 이 디렉터리에 있다. 프록시/정책/trigger는 전용 QA 자원에만 적용했고 확인용 버킷에 적용하지 않았다.

## UI 표준·테마·반응형

VM 메뉴와 공통 MoldDialog를 기준으로 버튼 32px/14px, 대화상자 버튼 반경 4px, 목록의 텍스트 포함 둥근 동작 버튼, 표 내부 스크롤과 작업 줄바꿈을 확인했다. 신규 동작 버튼은 공통 action/theme 토큰을 사용한다.

최종 UI의 라이트·다크 및 CSS viewport 360/768/1280px에서 실측했다. 최종 표본의 활성 텍스트 4.5:1 미달과 수평 넘침은 0건이며 최저 대비는 라이트 5.19:1, 다크 5.19:1이다. 입력 라벨 연결, 긴 키/UUID 줄바꿈과 표 내부 가로 스크롤을 확인했다. 높이가 긴 정리 화면은 본문 내부 세로 스크롤을 사용하며 UI 재시도 버튼을 실제 실행했다. JPEG의 실제 픽셀 크기와 CSS viewport를 별도로 기록했다. 일부 native JPEG 폭은 CSS viewport보다 10px 작으므로 이미지 크기를 viewport 실측값으로 사용하지 않았다. 전체 페이지를 축소한 그림으로 viewport 실측을 대신하지 않았다.

## 빌드·배포 검증

- WSL ext4에서 api, engine/api, engine/schema, server, plugins/storage/object/ceph 변경 모듈만 빌드했다. backend 122건, UI 7 suites/95건, 변경 Java Checkstyle, UI lint와 production UI build 통과.
- 전체 UI 테스트 탐색에서는 기존 AutoScaleToolbar/SnapshotPolicyList의 Node 14 `Array.at` 호환 오류를 확인해 중단했다. 해당 실행을 전체 회귀 PASS로 계산하지 않는다. Full Cloud/Full CI·GitHub Actions·qemu 빌드는 실행하지 않았다.
- backend 소스 `8bd6c058c6536221d81b4db77201d1cab91d97c1`, 최종 UI 소스 `2808a32623f512eb01ad385377ea1c2ff1cd2020`. JAR `b26f2567f342f544c2c7be8a955fa9f3282509acaeb41df834641cd45563ed51`, index `ce8238cfdd21bdc859ba37abe6e902e4e15af39ad581d925c3f45c2e9ae1be37`.
- JAR 변경/추가 항목 40개 외 204,588개 항목을 유지했다. 31/32 라이브러리 9개 및 정적 파일 636개가 일치한다. WEB-INF·설정·서버 디렉터리 보존, HTTP 200·Mold active, 호스트 3대씩 Up, Glue HEALTH_OK/RGW 3/3 확인.
- 추가 `purge_progress` 스키마는 같은 배포 버전에서 재적용 가능하다. 첫 31 배포의 readiness 스크립트가 이전 스키마 항목을 검사해 자동 롤백한 뒤 검사문을 수정하고 동일 JAR를 재적용했다. 최종 양쪽 실행 해시/신규 API/스키마를 재확인했다.
- 새 시험 키 12개 값을 현재 관리 로그와 검증 기간 Mold journal에서 검색해 노출 0건이다. 실제 값이나 private 스크립트/설정은 게시하지 않았다.
- 32번 기존 루트 공간 경보는 별도 운영 제약이다. 배포/백업은 NFS를 사용하고 기존 로그나 운영 데이터를 임의로 지우지 않았다.

## 보존·정리와 다음 작업

새 QA 버킷 30개, 저장소 4개, Cloud 계정 4개와 전용 RGW 사용자/키를 정리했다. 실제 보존기간 만료를 확인한 뒤 시험 Legal Hold를 해제하고 정확한 버전 삭제 후 빈 상태 일반 삭제로 정리했다. 관리자 purge나 원장 수동 보정은 사용하지 않았다. 진행 중 작업·예약·시험 trigger·임시 loopback 프록시 잔여 0이다. Windows/WSL 기존 FT 작업본의 HEAD·dirty diff·상태와 WSL 미추적 파일 해시를 보존했다.

**32번 [qa-bkt-1540-32-files](http://10.10.32.10:8080/client/#/buckets/3e952d59-a311-4a2b-86fe-d66ed38f050c?tab=browser) 하나를 유지했다.** 원래 11개 객체의 이름·크기·원시 S3 응답 바이트 SHA256과 계정 상세가 동일하며 최종 브라우저 목록의 로딩은 0이다.
