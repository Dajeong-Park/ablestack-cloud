# #1524 실패 복제 자원 정리 설계

선행 PR #1525의 배치 원장과 UI를 확장한다. 브랜치 기준은 `a83fad0c683`이며, #1518/#1519가 배포된 테스트 환경과 통합해 검증한다. 선행 PR을 포함하는 후속 PR이므로 #1524 자체 변경은 이 기준 커밋과 대조한다.

## 실패 처리

스토리지 복사 실패 응답·null 데이터·응답 부재를 성공으로 처리하지 않는다. 원래 실패 사유를 보존하고 NPE로 덮지 않는다. 실패 복사의 SNAPSHOT_ID는 물리 정리가 입증될 때까지 의존성으로 남긴다.

배치 실패 시 성공 생성 이력이 없고 준비된 GFS2 디스크로 재개할 수도 없는 대상만 cleanupRequired로 기록한다. Expunged/removed 표시만으로 이 대상의 재생성을 허용하지 않는다. 생성된 성공 VM, 기존 VM 시작 실패, 준비 완료 GFS2 대상은 정리 대상에서 제외한다.

## 물리 확인과 수렴

정리는 실제 Job 종료 뒤 배치·원본 잠금으로 직렬화한다. 정상 소유권·접근 권한, 원장 UUID·원본 볼륨 ID·기존 풀, 미연결·삭제 보호 없음·이미 제거된 실패 볼륨, 잔여 storage 참조 없음 조건을 모두 확인한다. 불일치 또는 남은 VM은 보존하고 정상 VM/볼륨 삭제 경로를 안내한다.

Mold Agent의 전용 읽기 명령이 같은 UUID를 참조하는 프로세스, RBD 최종/임시 이미지·trash·매핑 또는 정상 GFS2 마운트 내 관련 파일이 없음을 확인한다. 접근 오류·누락된 풀·미지원 응답은 부재 증거가 아니다. 알 수 없는 임시 파일이나 살아 있는 이미지를 강제로 지우지 않는다.

검증된 실패 볼륨만 트랜잭션에서 Expunged로 수렴시키고 stale SNAPSHOT_ID를 제거한다. 이미 제거 시 자원 계수가 차감됐으므로 계수는 다시 차감하지 않는다. 배치에 기록한 자동 VM 스냅샷만 기존 삭제 API와 참조 보호를 거쳐 정리한다. Linked 자식이 있으면 부모를 유지한다.

백그라운드 재시도는 제한 횟수와 지연을 적용하고 재시작 후 원장에서 복구한다. 정상 API `cleanupVMCloneBatch(requestid)`와 UI의 ‘실패 자원 정리 재시도’로 다시 확인할 수 있다. 실패 상태·사유를 보존하고, 비동기 정리 중에는 재생성·새 요청을 막는다.

GenericDao 상태 열과 갱신 시각은 각 필드 setter로 저장한다. 과거 상태 열이 QUEUED여도 정리 플래그로 복구 후보를 찾는다. 프레임워크 의사 Job은 정리 Job으로 저장·노출하지 않으며 실제 CleanupVMCloneBatchCmd만 동시 실행을 차단한다. Agent는 풀 자동 활성화/재생성 기능이 있는 일반 조회 함수를 사용하지 않고 기존 활성 풀의 정의·UUID·경로만 읽는다.

## 검증과 안전

22 rocky98-perftest 및 연결 디스크는 전원·디스크·QGA·마이그레이션 명령에서 제외한다. 기존 프로세스 PID/startTicks와 API/DB 메타데이터만 대조한다. 모든 실패 주입과 삭제는 qa1524 전용 UUID로 한정한다. WSL ext4에서 변경 Maven 모듈만 빌드하며 전체 Cloud/qemu 빌드는 실행하지 않는다. 관리 webapp의 WEB-INF/META-INF·설정과 비변경 JAR 항목을 보존한다.
