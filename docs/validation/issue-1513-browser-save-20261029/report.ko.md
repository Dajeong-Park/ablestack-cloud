# #1513 브라우저 최종 저장 추가 검증 - 사용자 확인 완료

2026-10-29 KST · Epic #1510 · PR #1514

사용자가 **“내가 직접 다운로드 정상 작동하는거 확인했어.”**라고 직접 확인하고 #1513 종료와 PR 병합을 요청했다. 앞서 요청한 `.tmp`에서 정상 파일명으로의 전환과 브라우저 저장 완료에 대한 최종 수락 근거로 기록한다. 에이전트가 브라우저 완료 화면이나 이벤트를 직접 관측했다고 주장하지 않는다.

이 확인으로 #1513의 추가 완료 기준을 충족한다. 추가 제품 코드 수정·배포나 전체 빌드는 수행하지 않았다. 이전의 UI 17개 조합·파일 전체 내용/해시·실패/중단/재시도/만료 검증과 시험 자원 정리 근거는 유지한다.

## 자동화 진단 이력

- 기존 Chrome Downloads의 `.tmp` 파일은 진단 근거로 보존했다. 수동 이름 변경이나 파일 복사로 브라우저 완료를 대신하지 않았다.
- 22에 별도 1GiB explicit off/raw DATA `qa1513-22-save-off-raw-data`를 생성해 두 위치에 구분 패턴을 기록하고 UI 추출 성공을 확인했다.
- 사용자가 Mold 탭을 활성화한 뒤에도 Windows 컴퓨터 조작 도구가 현재 Chrome URL을 판별하지 못해 당시 턴의 조작을 종료했다. 이 자동화 제약을 제품 오류로 단정하지 않았다.
- 위 도구 제약 이후 사용자가 직접 정상 다운로드를 확인했다. 자동화가 확인한 내용과 사용자 수락 근거를 구분한다.

## 정리와 보호 대상

전용 시험 볼륨·디스크 오퍼링을 API로 삭제했다. 해당 Primary/Secondary 이미지·Image 참조·SSVM symlink 잔여는 없고 링크는 HTTP 404다. 오퍼링의 비활성 이력과 기존 진단 파일은 보존한다.

22 `rocky98-perftest`에 전원·디스크·QGA·마이그레이션 요청을 보내지 않았다. 마지막 실환경 검증의 QEMU PID `219715`·시작 tick `191152358`은 최초와 같았다. 이번 수락·병합 단계에서는 테스트 클러스터에 접근하거나 변경하지 않는다.

## Epic 범위 확인

실제 연결 하위 이슈는 #1511·#1512·#1513 세 개다. #1511·#1512는 이미 완료됐고 #1513은 사용자 확인을 반영해 종료한다. **Epic 본문에는 별도 하위 이슈로 분리되지 않은 CL-02~06 다섯 항목이 남아 있다.** 현재 PR을 병합해도 이 항목들을 완료로 표시하거나 Epic 전체를 종료하지 않는다.
