# #1601 — 프로젝트 VPC ACL 규칙 권한과 실패 복구

31(GFS2)·32(Glue RBD) 관리 UI의 네트워크 ACL 상세 → **ACL 규칙** 탭을 개선했다. 테스트 VPC에 연결되지 않은 전용 ACL을 만들고 해당 ACL에서만 쓰기를 수행했다.

## UI 변경

- 규칙 추가, 편집, 삭제, 처음/마지막으로 이동, 드래그, CSV 가져오기, 태그 생성/삭제를 각각 해당 API 권한으로 검사한다. ACL이 속한 VPC의 프로젝트를 확인하고 그 범위에서 권한을 다시 조회한다. 읽기 전용은 규칙/태그 조회와 CSV 내보내기를 사용할 수 있고 규칙 추가는 비활성이다. 검색 결과만 보이는 상태에서는 전체 순서를 바꾸는 작업을 잠근다.
- **컴퓨트 → 가상머신 → NIC → 기존 네트워크 연결**을 기준으로, 공통 MoldDialog의 헤더·스크롤 본문·고정 하단 버튼과 세로 입력을 적용했다. ACL 이름과 규칙 번호를 문맥으로 표시하며, 탭의 추가·갱신·CSV 도구는 목록 위에 둔다. 상세 breadcrumb와 목록으로 돌아가는 링크는 기존 공통 구성을 따른다.
- 권한 조회 실패 시 목록을 보여 주고 쓰기를 잠근 채 재시도할 수 있다. 권한 변경·프로젝트/화면 이동으로 작업이 끝나면 편집과 가져오기 입력 및 늦은 응답을 폐기한다. 401 권한 거부는 입력을 보여 준 채 닫기/재조회만 제공한다. 431/530·전송·비동기 실패에서는 입력과 CSV 파일을 보존한다. 작업 ID를 받은 뒤 결과 조회가 실패하면 동일 작업을 확인할 수 있다.
- 서버 API·프로젝트 역할 정책·관리 JAR는 변경하지 않았다.

## 검증

| 역할 | ACL 규칙 조회 | 편집·이동·추가·삭제·태그 쓰기 | CSV 가져오기 |
| --- | --- | --- | --- |
| 관리자 | 허용 | 허용 | 허용 |
| 프로젝트 소유자·멤버·도메인 관리자 | 허용 | 허용 | 현재 API 권한에서 미노출 |
| 프로젝트 읽기 전용 | 허용 | 숨김/비활성, 쓰기 요청 0건 | 미노출 |
| 같은 도메인·다른 도메인 비회원 | 프로젝트 선택 후보와 직접 상세 접근 차단 | 쓰기 요청 0건 | 미노출 |

- 31·32의 관리자·소유자·멤버·도메인 관리자·읽기 전용·비회원을 실제 로그인 화면에서 확인했다. 32 읽기 전용의 CSV 다운로드 시작 이벤트에서 규칙 6개와 인용 필드를 대조했다(파일 저장 완료 이벤트는 확인하지 못했다). 역할별 API 쓰기 **98건**을 대조했다. 이 중 같은 도메인 비회원에 대해서는 읽기·권한 조회 거부도 별도로 확인했다.
- 양쪽에서 잘못된 CIDR로 인한 실제 편집 작업 실패 후 입력을 고쳐 저장했고, 관리자 CSV 제출, 처음으로 이동, 드래그를 실행했다. CSV의 따옴표로 묶인 쉼표가 실제 규칙 설명에 보존됐다. 32에서 제어된 530 뒤 같은 CSV 미리보기로 재시도해 실제 규칙이 생성됐다.
- 시험 브라우저에 한정해 401·431·530·연결 오류 응답을 재현했다. 401은 권한 재조회만 제공했고, 나머지 실패는 같은 입력에서 재시도할 수 있었다. 양쪽 최종 번들에서 권한 조회 530 뒤 읽기 유지·쓰기 차단·재시도 복구를 확인했다. 32에서 권한 조회 보류 중 기본 보기로 전환하자 대기 요청이 취소됐으며 쓰기 요청이 없었다. 늦은 응답, 직접 핸들러 호출과 접수된 작업 재확인은 집중 테스트에 포함했다.
- 양쪽에서 프로젝트 → 기본 보기 → 프로젝트 왕복, 편집 입력 중 VPC 이동 후 복귀, VPC의 ACL 링크 → 상세 → ACL 규칙 탭을 검증했다. 전환과 이동 중 쓰기 요청 0건을 확인했다.
- 390×844·768×1024·1280×900에서 양쪽 라이트/다크 **12개** 조합의 브라우저 실제 너비, 본문·페이지 가로 넘침, footer, 세로 입력, 전경/배경 색을 기록했다. 캡처는 브라우저 원본 JPEG이며 별도 이미지 크기도 기록했다.
- 로컬 WSL ext4에서 변경 파일 lint, 집중 테스트 26개 및 UI production build를 통과했다. 두 관리 서버에서 정적 파일 662개 해시, WEB-INF/META-INF와 서비스 보호 항목, 관리 JAR 해시, /client/ HTTP 200을 확인했다.

시험 ACL과 규칙은 사용자 확인을 위해 유지한다. 두 ACL은 Tier에 적용하지 않았다. 기존 규칙, Tier 연결 ACL, VM 기본 NIC와 프로젝트 멤버십이 이전 상태와 일치한다.
