# SP-04 (#1498) 정책 생성 태그 모델

2026-10-26. 기준 ccf644c59ae, Epic #1494. 전체 목록과 볼륨 상세의 정기 스냅샷 생성 작업은 같은 FormSchedule을 사용하며, 볼륨 정기스냅샷 탭에서 저장 결과를 확인한다.

## 문제와 결정

기존 X는 AntD 태그를 숨기지만 handleDeleteTag가 비어 있어 createSnapshotPolicy 요청에는 삭제한 태그가 남는다. 그룹 blur와 keyup.enter는 필드 간 이동·확인/취소 클릭과 겹치며, 필수/중복 키 검사 없이 배열에 추가한다.

화면과 제출은 단일 tags 배열을 사용한다. key를 안정 키로 쓰고 close.prevent로 AntD 자체 숨김을 막은 뒤 배열에서 실제 제거한다. 키 앞뒤 공백을 제거하고 빈 키/공백 값과 중복 키를 거부한다. 중복 키의 값 덮어쓰기를 허용하지 않는다. API는 Map이므로 동일 키의 여러 값을 표현할 수 없다. 값의 의미 있는 앞뒤 공백은 보존한다. 입력 길이 255는 기존 VM 태그 입력과 같다.

입력은 확정 또는 취소해야 한다. blur는 저장하지 않는다. Enter는 prevent/stop한 keydown에서 한 번 확정하고 IME 조합 중에는 확정하지 않는다. Escape/취소는 초안을 버리고 추가 버튼에 초점을 돌린다. 정책 확인에 유효한 초안이 남으면 같은 모델에 한 번 확정한 후 검증/제출한다. 빈/중복 초안이면 오류와 초점을 제공하고 제출하지 않는다. API 실패는 일정과 확정 태그를 유지한다. 전송 중 모델 변경과 중복 제출은 차단한다.

## 권한과 API 계약

VM ResourceTags와 동일하게 createTags가 없으면 태그 추가 UI를 제공하지 않는다. createSnapshotPolicy 권한도 있어야 한다. 권한이 사라지면 초안/태그를 제거하며 제출 직전에도 현재 권한·사용자/프로젝트/리소스 문맥을 확인한다.

이 화면의 태그는 아직 서버에 없는 생성 초안이다. 추가와 X 삭제는 로컬 모델만 변경하며 createTags/deleteTags API를 호출하지 않는다. 따라서 createTags가 있고 deleteTags가 없는 역할도 자기 초안은 취소/삭제할 수 있다. 이미 저장된 정책 태그 편집/삭제와 구분한다. createSnapshotPolicy(tags)는 백엔드에서 태그를 함께 생성하며 별도 createTags 엔드포인트 호출 권한과는 독립 계약이다. UI에서 태그를 숨기는 것은 VM 메뉴와 맞춘 제한이고, 이 변경으로 서버 ACL을 확장하지 않는다. 정책 upsert의 전체 태그 교체 계약은 SP-05가 다룬다.

## UI 표준

컴퓨트 > 가상머신 ResourceTags의 세로 입력, 32px AntD 입력·확인/취소 아이콘 버튼, dashed 추가 버튼, 6px 간격과 줄바꿈 태그를 따른다. MoldDialogActions의 하단 취소/확인과 라이트/다크 테마 토큰을 유지한다. 입력 중 태그가 정책 생성 시 저장됨을 안내한다. 전역 VM CSS/태그 컴포넌트는 수정하지 않는다.

## 검증 계획

- 실제 AntD 태그 X/키보드와 createSnapshotPolicy payload를 연결하는 검사, 빈/중복/취소/blur/IME/확인·실패/재시도·중복 제출·권한/문맥 경합 회귀.
- 31 GFS2·32 RBD 전용 1GiB 볼륨에서 목록 생성창과 볼륨 탭의 실제 UI 추가→삭제→생성. 요청·정책 API·독립 DB 대조.
- 남긴 태그는 실제 자연 예약 스냅샷에 전달되고 삭제/취소한 태그는 없음을 확인한다. 수동 createSnapshot(policyid)는 스케줄러 전달 검증으로 대체하지 않는다.
- 제한 역할의 태그 UI와 실제 API 허용/거부를 확인한다. 양쪽 라이트/다크×390/768/1280, 긴 한글/키보드·실패 입력 보존·재시도 회귀.
- 전용 정책/예약/스냅샷/볼륨/태그·시험 역할/계정을 정상 API로 정리하고 DB/스토리지·기존 자원·dirty FTCTL 작업 보존 대조.
