# SP-13 통합 회귀와 UI 표준 정렬 설계

대상은 #1507 및 Epic #1494다. SP-01~12가 함께 반영된 브랜치에서 31 GFS2와 32 RBD를 실제 API·UI·job·DB·스토리지로 대조한다. 기존 운영 자원과 별도 FT 작업 트리를 보존한다.

## UI 구조

기준은 `컴퓨트 > 가상머신`의 공통 `AutogenView`, `ListView`, `ResourceLayout`, `ResourceView`, `InfoCard`, `MoldDialog`다.

- 정책 검색 컨트롤에 공통 검색 스타일과 table-cell 배치를 적용한다. Breadcrumb 왼쪽에는 경로·도움말·업데이트·프로젝트 스위치, 오른쪽에는 생성/선택 작업과 검색을 놓는다. 검색이 생성 버튼 아래로 불필요하게 내려가는 원인을 제거한다.
- Breadcrumb 생성 동작은 `MoldDialog`의 `md=720px` 프리셋과 표준 헤더·스크롤 본문·고정 하단 작업 영역을 사용한다. 모바일 폭은 공통 반응형 제한을 따른다.
- 볼륨 선택은 예약 폼의 첫 필드다. 별도 선택 화면과 ‘계속하려면 선택’ 빈 화면을 없애고, 처음 열었을 때부터 주기·시각·보관 수·시간대·추가 Zone·태그를 같은 폼에 표시한다. 유효한 볼륨과 그 정책 조회가 확정될 때까지 제출을 막는다.
- 볼륨을 바꾸면 이전 예약 초안·태그·정책/한도/Zone 응답을 새 볼륨에 섞지 않는다. 생성 요청 중 볼륨 변경과 중복 제출을 막는다. 볼륨 상세에서 호출하면 고정된 볼륨 문맥을 유지한다.
- 생성창을 다시 열 때 새 generation을 사용해 이전 창의 상태를 재사용하지 않는다. 정책 페이지의 컨테이너 폭 변경은 공통 Affix 관찰 경로에 포함한다.
- 정책 상세는 같은 좌측 정보 카드·우측 컨텐츠 카드와 VM의 탭 방향 정책을 사용한다. 탭이 하나여도 정책의 ‘상세’ 탭을 표시한다. 상세 필드·예약/최근 실행 정보는 기존 정책 컨텐츠를 유지한다.

## 통합 중 발견한 공통 오류

`InfoCard`의 장식용 계정/아이콘 조회는 반환 Promise를 종결하지 않거나 호출자가 소비하지 않는 reject를 만들었다. 조회를 단일 async 함수로 통합하고 현재 경로·자원·로그인·프로젝트 및 unmount를 검사한다. 취소·실패·권한 없는 장식 조회는 화면 이동을 실패시키지 않으며 늦은 아이콘을 다른 자원에 넣지 않는다.

테마 조회는 발견된 `listGuiThemes` 권한을 사용한다. 인증된 페이지 초기화는 정적 설정을 먼저 적용하고 역할 발견 후 허용된 사용자만 계정/도메인 테마를 조회한다. 기본 ReadOnly의 금지된 테마 API 호출을 제거한다. 정적 브랜딩과 테마가 없는 경우의 fallback은 유지한다.

실제 역할 전환에서 로그아웃 직후 정책 화면의 watcher가 새 조회를 보내 401 알림을 만드는 문제도 확인했다. 정책 조회 권한이 해제되면 목록·상세와 진행 중 조회 generation을 즉시 무효화하고 새 조회를 차단한다. 이전 응답은 화면을 복원하지 않는다.

기본 ReadOnly는 `listVolumes`를 사용할 수 있지만 볼륨 UI 경로에 필요한 `listVolumesMetrics`는 없다. 정책에서 볼륨 링크를 누르면 대시보드로 이동하는 것을 양쪽에서 확인했다. 정책 목록·정보 카드·상세의 볼륨 링크는 목적지 UI 권한을 검사해 제한된 역할에는 이름만 표시한다. 허용된 링크는 프로젝트 ID를 보존한다. 볼륨 경로 자체의 API/역할 정책은 변경하지 않는다.

정책 상세에서 금지된 목록 URL로 이동할 때 조회 차단보다 먼저 목적지의 목록/상세 모드를 적용한다. 이전 상세 레이아웃이 남아 빈 필드와 잘못된 볼륨 링크를 표시하지 않도록 한다.

서버가 편집을 저장한 뒤 응답만 잃는 실제 XHR 시험에서 명시적 재조회가 이전 보관 수로 폼을 재생성하는 결함도 재현했다. 재조회 시작 시 버릴 초안을 해제하고, 새 정책과 볼륨을 모두 받은 뒤에만 편집 폼을 마운트한다. 늦은 응답의 generation 검사는 유지하며, 새 값·태그로 초기화되고 재저장이 자동 발생하지 않는지 검사한다.

정책 상세의 단일 삭제 성공 뒤 즉시 상세를 재조회하면 이미 삭제된 UUID가 431이 되고, 대화상자의 scope도 지워져 after-close 결과를 잃었다. 확인된 삭제 ID를 refresh 이벤트에 포함하고 해당 상세 재조회만 건너뛴다. 닫힘 결과와 원래 scope를 확인한 뒤 늦은 조회를 무효화하고 프로젝트·검색·정렬·페이지 크기를 보존한 목록의 첫 페이지로 복귀한다. 삭제된 ID 필터와 상세 전용 쿼리는 제거한다. 결과가 미확인이거나 문맥이 바뀐 경우에는 이 성공 경로로 이동하지 않는다.

## 관리자 중지 상태 보존

31·32 모두에서 관리자가 중지한 정책을 일반 소유자가 편집하면 `fordisplay`의 생성 기본값 때문에 예약이 다시 활성화되는 문제를 재현했다. 일반 소유자는 이 관리 매개변수를 설정할 수 없다. 기존 정책 편집 시에는 볼륨·정책 행 잠금 안에서 저장된 display 값을 보존한다. Root 관리자의 명시적인 중지/재개, 새 소유자 정책의 기본 활성화 및 내부 복사 호출은 기존 계약을 유지한다. 보관 수만 바꿀 때 중지 상태와 다음 예약 부재도 그대로 유지되는지 API·DB·UI로 검증한다.

## 시간대 API 검증

실제 양쪽 API가 `Bad/Timezone`을 GMT로 바꾸어 저장하는 결함을 재현했다. Java `TimeZone.getTimeZone`의 미지원 ID에 대한 조용한 GMT fallback이 원인이다.

`SnapshotPolicyInputValidator.validateTimezone`에서 null/빈 값 및 GMT fallback을 거부하고, 정상 Java 시간대 ID·기존 별칭·유효한 사용자 GMT 오프셋의 정규화는 유지한다. 정책 저장 전에 실행하여 잘못된 입력은 431로 반환한다. API 매개변수나 DB 스키마는 바꾸지 않는다. DST 계산은 기존 스케줄러의 봄 gap 전방 정규화·가을 중복 시각 표준 오프셋 계약을 검사하며 서버 시계는 변경하지 않는다.

## 공간·배포·회귀 판정

31의 전역 `secondary.storage.capacity.threshold=0.90`을 유지한다. 열린 파일을 제외한 오래된 WAL의 내용·해시·metadata를 별도 파일시스템에 보존하고 원래 숫자 경로를 연결한 뒤 준비 상태·PID·고정 시각 조회·새 수집을 확인한다. 보존 사본은 활성 링크 대상이므로 시험 정리 대상이 아니다.

변경 server 모듈만 WSL ext4에서 package한다. 실제 JAR과 빌드 기준의 관련 클래스 및 비대상 메서드를 대조하고 클래스 2개만 교체한다. UI는 최종 소스에서 빌드하고 정적 파일만 배포한다. WEB-INF/META-INF·관리 설정·큰 비UI 파일·비대상 JAR entry와 롤백 사본을 보존한다. 전체 Cloud/FTCTL 빌드를 시작하지 않는다.

실환경 결과, 응답 주입, 자동 검사와 환경상 미지원/시험 불가를 분리한다. 추가 Zone·암호화 디스크가 없는 환경을 다중 Zone 실물 성공으로 표현하지 않는다. 자연 예약은 수정 서버에서 2회 이상 발생한 system job과 태그·사본·maxsnaps 정리를 확인하고 직접 스냅샷 API 호출과 구분한다. 정상 제품/API 정리 후 전용 정책·예약·태그·스냅샷·볼륨·미완료 job·비종결 참조·실물 잔여를 확인한 뒤 #1507과 Epic을 종료한다.
