# SP-05 — 기존 정책 편집·관리자 예약 중지/재개

대상 #1499 / Epic #1494. 기준 `3364ed20b88`. 선행 SP-04/06/08의 태그·예약·입력 계약을 유지한다.

## 사용자 동작과 표준

정책 전체 목록의 행 작업과 볼륨 정기스냅샷 탭에서 **정책 편집**을 제공한다. 기존 생성창은 신규 등록 전용이며 등록된 주기 비활성화는 그대로다. 편집은 볼륨·주기·정책 UUID를 고정하고 일정·시간대·보관 수·태그·추가 Zone을 로드한다. 가상머신 메뉴와 같은 MoldDialog/세로 AntD 폼·명시적 대상 요약·취소→저장·기본 토큰·반응형 고정 footer를 사용한다.

관리자이고 updateSnapshotPolicy 권한이 있을 때 **예약 중지/재개**를 제공한다. fordisplay는 단순 표시 토글이 아니라 일반 사용자 목록 표시와 미래 예약을 함께 바꾼다. 상태와 영향을 확인한 뒤 실행하며, 현재 시작된 스냅샷 작업은 취소하지 않는다. 재개는 현재 시각 이후의 다음 일정이다. 일반 사용자는 이 관리자 작업을 보지 않는다. active는 API 응답에 없으므로 화면에서 존재하지 않는 실행 상태를 추정하지 않는다.

## 읽기·저장 계약

대화상자를 열면 listSnapshotPolicies(id/volumeid)와 listVolumes(id)로 최신 정책/소유 범위/볼륨을 읽는다. ID·볼륨·주기 불일치나 삭제·권한 오류는 저장을 막는다. 재조회는 명시적이며 오래된 응답은 로그인·프로젝트·경로·대상 전환 후 적용하지 않는다.

편집은 createSnapshotPolicy upsert 한 요청이다. 기존 UUID를 확인하고 태그는 미변경 값을 포함한 전체 배열을 보낸다. 명시적 태그 전체 제거는 태그 없는 전체 교체다. 태그 권한이 없는 경우 기존 태그를 읽기 전용으로 보존한다. 관리자 편집은 기존 fordisplay를 함께 보내 중지 정책이 편집만으로 재개되지 않도록 한다. 오류와 실패 재시도는 초안을 보존한다.

createSnapshotPolicy에 선택적인 id(UUID)를 추가한다. id가 있으면 해당 볼륨+주기의 정책이 그 ID와 일치해야 한다. 서버의 기존 upsert 잠금/트랜잭션 안에서 검사하여 삭제/다른 주기/대상 변경 후 새 정책 생성으로 바뀌지 않게 한다. 기존 id 없는 생성 API의 동작은 유지한다.

기존 zoneids 미지정은 보존이고, 비어 있는 목록은 현재 서버가 보존으로 취급한다. 편집의 추가 Zone 전체 해제를 위해 id와 함께 사용하는 clearzoneids=true를 추가한다. zoneids와 동시 지정은 거부한다. 추가 Zone 상세만 지우고 소스 Zone 및 별도 storage 상세는 유지한다. 조회 실패/권한 부족에서 기존 Zone을 잃지 않는다. GFS2/RBD에 StorPool 전용 storageids/usestoragereplication UI는 추가하지 않는다.

관리자 중지/재개는 updateSnapshotPolicy(id,fordisplay)의 실제 async job 완료를 기다린다. 작업 제출 전 최신 대상·상태·권한을 다시 확인한다. 같은 대화상자의 중복 제출을 막고 서버 오류/job 실패 후 상태를 재조회해 재시도한다. 실행 중 편집·중지·재개는 SP-06의 동일 job/snapshot 참조 보존을 따르며 실행 중 정책 삭제 431은 서버 권위로 유지한다.

## 검증과 배포

- 네 주기의 정확한 디코딩/인코딩, 같은 UUID upsert, 태그 보존/선택 삭제/전체 제거, Zone 보존/명시 해제, 중지 상태 편집을 검사한다.
- 삭제된/바뀐 대상의 편집을 거부하고 초안 보존·재시도·중복/늦은 응답·권한 소실을 검사한다. 일반 사용자·조회 전용·프로젝트의 실제 UI/API를 검증한다.
- 31 GFS2·32 RBD의 전용 자원을 사용하고 정책 메뉴·볼륨 탭의 실제 UI를 대조한다. 자연 예약의 실행 중 작업을 한정된 watchdog으로 관찰하고 시작 작업의 참조 보존/완료·다음 예약을 확인한다.
- 변경 API/server 모듈만 WSL ext4에서 빌드한다. UI lint/집중 검사/production build 후 정적 파일과 허용 클래스만 배포하며 WEB-INF·설정·기존 FTCTL·운영 자원/dirty 작업 트리를 보존한다. 전체 Cloud 빌드나 Actions dispatch는 하지 않는다.
- 실제 VM 표준과 라이트/다크 × 390/768/1280px에서 비교하고 이미지 포맷·디코딩 치수를 확인한다. 시험 자원과 API/DB/스토리지 잔여를 정상 경로로 정리한 뒤 완료 판정한다.
