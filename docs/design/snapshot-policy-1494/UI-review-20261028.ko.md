# 스냅샷 정책 후속 UI 검토

대상은 SP-13 완료 뒤 사용자가 요청한 목록 갱신 흔들림·정기스냅샷 시간 드롭다운 가독성·검토 데이터 보존이다. 기존 Epic 이력과 구분해 같은 구현 브랜치에서 보완한다.

## 목록 갱신

같은 범위를 갱신할 때 기존 rows는 보존했지만, `storageActionReady=false` 때문에 ListView의 actions와 Breadcrumb 생성 작업을 제거했다. 선택 열의 존재 여부가 groupAction에 의존해 체크박스 열도 제거되고 테이블 자동 너비가 다시 계산됐다. 양쪽 실제 XHR을 보류했을 때 생성 버튼과 선택 열이 사라졌다.

- 정책 목록의 선택 열 표시 가능 여부를 정적 작업 정의·실제 API 권한·검색 유효성으로 판단한다. 실행 가능 여부는 기존 `selectionDisabled`·최신 범위/조회 상태 검증으로 통제한다.
- 같은 범위의 성공 데이터가 있는 동안 Breadcrumb 작업을 유지하고 재조회/갱신 실패 상태에서는 disabled로 표시한다. 행 작업은 기존 최신 상태 guard를 유지한다.
- 범위/사용자/권한이 바뀌면 기존 데이터와 작업을 계속 숨긴다. 초기 조회·다른 소유자 조회·권한 오류를 마지막 성공 데이터 보존과 혼동하지 않는다.
- 요청을 보류한 실제 브라우저에서 생성·선택/선택 삭제 작업, 열의 위치/폭, 행 ID와 체크 상태를 전/중/후 대조한다. 503 뒤 재시도도 검사한다.

## 시간 선택 드롭다운

AntD TimePicker의 body portal은 MoldDialog 내부 색상 범위에서 벗어난다. 실제 dark 배경 `rgb(39,46,54)`에서 옵션 글자는 `rgba(0,0,0,0.65)`였다.

`FormSchedule`의 TimePicker에 전용 `snapshot-policy-time-dropdown` popup class를 지정한다. 공통 VM 테마 토큰을 사용해 배경·일반/선택/hover/비활성 글자·테두리·현재 시각 링크를 처리한다. AntD의 `column > li.cell .inner` 선택자보다 우선하도록 한정된 popup 범위 안에서 같은 구조를 사용한다. 다른 메뉴의 날짜/시간 선택기는 변경하지 않는다. 매일·매주·매월과 생성/편집이 같은 폼을 사용한다.

## 검토 데이터 보존

31·32에 `UI검토-SP-{31|32}-20261028` 이름의 전용 DATADISK·네 주기 정책·실제 자연 예약 스냅샷을 남긴다. 페이지 이동용 정책과 모든 간격을 선택할 수 있는 빈 생성 검토 볼륨을 구분한다. 실제 자연 예약을 확인한 뒤 예약을 중지해 오래된 검토 스냅샷이 보관 수 정리로 자동 교체되지 않게 한다.

**명시적인 사용자 삭제 요청 전에는 이 데이터·정책·스냅샷을 정리하지 않는다.** 운영 자원에는 쓰지 않는다. 전역 용량 임계값 0.90과 기존 WAL 보존 링크·FT 작업을 유지한다. UI 정적 배포는 WEB-INF/META-INF·설정·JAR/PID·비UI 파일을 보존한다. 전체 Cloud/FTCTL 빌드는 수행하지 않는다.
