# SP-11 선택 삭제와 소유 범위 검색

선택 삭제는 가상머신의 공통 목록 체크박스·선택 작업과 MoldDialog를 사용한다. 선택 범위는 현재 페이지이며 페이지/검색/정렬/크기 또는 보안 범위가 바뀌면 해제한다. 다른 페이지까지 숨은 선택을 유지하지 않는다. 대화창을 열 때 정책 ID/볼륨/주기의 집합을 고정하고, 각 대상의 최신 정책·볼륨과 소유자를 읽어 요약한다. 제출 직전 다시 읽어 일정·태그·소유자 등의 지문이 달라졌으면 재조회와 새로운 확인을 요구한다. 취소/권한 상실/프로젝트·사용자·세션 전환/중복 제출에는 쓰기를 보내지 않는다.

`deleteSnapshotPolicies(ids=...)`는 전체 ID/원본 볼륨 존재와 ACL을 먼저 검사하고 정책별 트랜잭션으로 삭제한다. 뒤쪽 정책의 실행 중 job 등 런타임 오류가 발생하면 앞쪽 삭제는 이미 커밋될 수 있다. API 전체 원자성을 새로 보장하지 않는다. UI는 이 계약을 확인창에 알리고 단일 ids 요청 후 캡처한 ID만 재조회한다. 정상 응답과 부재 확인을 모두 얻은 대상만 성공으로 판정한다. 오류/응답 유실 후 부재는 결과 미확인으로 구분하고 성공으로 추정하지 않는다. 남은 정책은 최신 조회와 명시적인 재확인을 거쳐서만 재시도한다. 기존 스냅샷은 삭제하지 않는다. 조회 오류가 있으면 재삭제 대신 결과 조회를 제공한다.

검색은 기존 VM의 고급 검색 팝오버·세로 폼·공통 32px 입력/선택 컨트롤을 사용한다. 정책 UUID, 볼륨, 관리자/도메인 관리자의 도메인·계정·하위 도메인 포함, root 관리자의 미래 예약 플래그를 지원한다. 프로젝트는 공통 상단 선택기를 사용하고 URL에 범위를 기록한다. 계정은 도메인과 함께 지정하며 프로젝트와 소유자 필터를 동시에 적용하지 않는다. 개인 범위는 `ignoreproject=true`, 지정 프로젝트는 `projectid`, 전체 보기는 `projectid=-1&listall=true`(접근 가능한 개인/프로젝트 포함)로 구분한다. URL 복원/정렬/검색/count/삭제 후 마지막 페이지 복귀는 SP-09 계약을 유지한다. 잘못된/권한 없는/미지원 검색은 오류를 표시하고 API를 보내지 않는다.

현재 서버는 선언한 `fordisplay`를 검색에 적용하지 않고 개인 ID 조회에서도 프로젝트를 배제할 수 없다. nullable 플래그 조건과 명시적 `ignoreproject`를 추가하며 기존 생략 시 동작은 유지한다. 프로젝트와 계정/도메인 및 프로젝트와 ignoreproject의 모순 조합은 거부한다. API 프레임워크는 root 외의 fordisplay 입력을 무시하는 기존 계약이므로 UI에서는 역할에 따라 제공/URL 요청을 차단하고 서비스에 직접 전달된 비root 플래그도 거부한다.

실제 API에서 도메인 관리자의 전체 보기는 공통 ACL 도우미의 개인 프로젝트 구성원 목록 때문에 자기 계정 정책만 반환했다. 도메인 관리자의 `projectid=-1`은 자기 도메인과 하위 도메인을 경계로 개인/프로젝트 정책을 함께 검색한다. 일반 사용자는 자기 계정과 구성원 프로젝트의 합집합을 유지하고 root는 전체 범위를 사용한다. 지정 프로젝트의 접근 검증은 기존 공통 ACL 도우미를 유지한다.

실제 브라우저의 공통 요청 인터셉터가 `ignoreproject`를 클라이언트 전용 값으로 제거하는 경로도 확인했다. 신규 서버 매개변수를 사용하는 `listSnapshotPolicies`에만 GET/POST 전송을 허용한다. 다른 API의 기존 동작은 유지한다. `listAccounts(domainid,isrecursive=false)`도 root에서는 하위 도메인 계정을 반환하므로 후보를 선택한 도메인의 정확한 ID로 제한한다. 원본 페이지의 읽은 행 수와 적합 후보 수를 분리해 중간에 빈 적합 페이지가 있어도 누락 없이 계속 조회한다.

주기·Zone·활성 상태·customid·태그 필터는 이번 범위에서 제외한다. 현 조회 API가 이를 필터링하지 않으며, 이슈의 소유 범위/ID/관리자 플래그와 다른 검색 계약 확장이 필요하다. 미래 예약은 fordisplay의 운영 의미이며 active 내부 플래그와 혼용하지 않는다. 볼륨 이름 키워드는 기존 LIKE 검색이다. UUID 입력은 별도 정확 일치 검색으로 제공한다. 기존 fordisplay 생략은 활성/중지 모두를 반환한다.

31 GFS2·32 RBD에서 전용 중지 정책을 20개 초과로 준비하고 API/SQL 결과와 실제 UI의 소유/프로젝트/역할/페이지/선택/부분 실패·응답 유실을 대조한다. 전역 임계값 0.90과 기존 운영 자원을 보존하며, 시험 자원은 정상 API로 정리한다. 전체 Cloud 빌드나 Europa 병합은 포함하지 않는다.
