# SP-06 — 일정 재계산과 실행 경합 보호

대상: #1500, 부모 #1494. 구현 기준 `c4122d871af`, 변경 모듈 `server`.

## 예약 계약

- 일정·시간대·주기·active·display가 실제로 바뀌면 같은 정책 UUID의 예약을 조정한다. 보관 수·태그만 변경하거나 같은 값을 다시 제출하면 예약 시각과 작업 참조를 유지한다.
- API 변경은 마지막 폴링 시각이 아닌 현재 시각을 기준으로 다음 미래 실행을 계산한다. 기존 시험용 TestClock은 유지한다.
- 시작하지 않은 예약은 갱신할 수 있다. 이미 수락된 비종결 async job은 예약 행의 job/snapshot ID와 원래 예정 시각을 유지한다. 정책의 새 일정은 즉시 저장하고 작업 완료 후 최신 정책으로 다음 미래 예약을 계산한다. 실행 중 놓친 슬롯을 소급 중복 실행하지 않는다.
- 중지/표시 해제는 미래 예약을 제거한다. 이미 수락된 작업은 완료시키고 재개하면 최신 정책을 사용한다.
- 정책 삭제의 FK는 예약 행까지 cascade한다. 따라서 작업이 진행 중이면 431과 재시도 안내로 삭제를 거부하고 정책·태그·참조를 보존한다. 완료 후 삭제는 기존 계약대로 허용한다.
- 실제 API 경로에서 볼륨의 Snapshotting 상태가 기존 정책 편집도 막는 것을 확인했다. upsert 잠금 안에서 기존 정책 존재를 확인해 **기존 정책 편집만** 허용한다. display=true인 Snapshotting 상태의 신규 정책 등록과 Destroy 상태는 계속 거부한다.

## 동시성 및 복구

모든 변경은 같은 트랜잭션 안에서 **정책 행 → 예약 행** 순서로 잠근다. 없는 정책의 생성은 기존 볼륨별 GlobalLock으로 직렬화하며 성공/실패 모두 참조를 해제한다. 정책 갱신이 실패하거나 예약 갱신이 실패하면 예외를 바깥 트랜잭션에 전파한다.

폴러의 due 목록은 후보 목록이다. 실제 할당 전에 최신 정책/예약을 다시 잠그고 ID·소유 볼륨·활성/표시·예정 시각·job 미할당을 재검사한다. 스냅샷 할당, 내구성 작업 큐 제출, 예약의 job/snapshot 참조를 같은 트랜잭션에 기록한다. 기존 `submitAsyncJob(job, "SnapshotPolicy", policyId)` 큐 경로를 사용해 커밋 전에 작업자가 실행되는 창을 없앤다. 다른 프레임워크 모듈과 DB 스키마는 변경하지 않는다.

완료 처리는 예약 행 ID와 예상 async job ID를 다시 대조한다. 오래된 완료 후보가 새 작업을 지우지 않는다. SUCCEEDED/FAILED는 종결로 처리하고 IN_PROGRESS와 알 수 없는 상태는 보존한다. 물리적으로 만료된 작업 행은 기존 계약대로 종결로 취급한다.

관리 서비스 시작 시 미래 및 지연된 미실행 예약을 그대로 유지한다. 비활성 예약은 제거하며 진행 중 작업은 유지한다. 종결 작업은 최신 정책으로 다음 미래 예약을 만든다.

## UI 범위와 검증

이 변경은 예약 엔진과 API 계약이다. UI/CSS/번역·공통 VM 컴포넌트를 변경하지 않는다. **컴퓨트 > 가상머신**을 표준으로 기존 정책 메뉴·볼륨 탭의 생성/갱신/오류 표시를 실제 브라우저에서 확인한다. 일정 편집과 관리자 중지/재개 버튼의 신규 UI는 #1499가 담당하며 입력 범위 계약 #1502도 선행한다.

검증은 변경 server 모듈의 집중 단위 검사, 31 GFS2·32 RBD의 API/실제 UI, 독립 DB·작업 이력·백업 파일을 연결한다. 실제 300초 폴링과 실제 시간을 유지하고 SQL 상태 변경이나 수동 createSnapshot으로 자연 실행을 대신하지 않는다. 시험 전용 1GiB 볼륨의 스냅샷 행 잠금에는 자동 해제 제한을 둔다. 실행 중 관리 프로세스 강제 종료나 다중 관리 노드 장애 조합은 이 단일 노드 실험의 통과로 주장하지 않는다.

배포는 server 모듈에서 생성한 변경 클래스 계열만 기존 관리 JAR의 백업 복사본에 적용한다. 다른 JAR 항목·WEB-INF·기존 UI·설정 해시를 대조하고 기동/로그인/API를 확인한다. 전체 Cloud 빌드, qemu/FTCTL 배포 또는 Europa 병합은 수행하지 않는다.
