# SP-09 — 정책 전체 목록 정렬·페이지·URL 계약

#1503 / Epic #1494. 기준 `625484329bb5fcdfa537aa65786674a04ce1855c`. 기존 UI의 현재 페이지 정렬을 서버 정렬로 바꾸며 가상머신 메뉴의 공통 표·정렬 화살표·검색·페이지 컨트롤을 유지한다. 새 CSS나 별도 목록 화면은 만들지 않는다.

API `listSnapshotPolicies`에 `sortkey`/`sortorder`를 추가한다. 기본값은 기존 ID 내림차순이다. 허용 키는 `id`, `intervaltype`, `maxsnaps`, `schedule`, `timezone`, `volumename`이며 방향은 `asc`/`desc`다. 대소문자는 정규화하고 알 수 없는 키·방향·SQL 형태 입력은 SQL 수행 전에 431로 거부한다. SQL 표현식은 고정된 허용 목록에서만 선택하고 모든 동일 값은 같은 방향의 정책 숫자 ID로 구분한다. 기존 ACL·소유 범위·볼륨/ID/키워드 조건과 searchAndCount를 유지한 채 ORDER BY 후 LIMIT를 적용한다. 볼륨명은 기존 1:1 volumeJoin의 name을 사용해 건수/정책 중복을 만들지 않는다.

| 정렬 키 | 의미 |
|---|---|
| id | 내부 정책 ID 숫자 순서(기본 desc); UUID 문자열 순서와 다름 |
| intervaltype | HOURLY=0, DAILY=1, WEEKLY=2, MONTHLY=3 |
| maxsnaps | 보존 수 정수 |
| timezone / volumename | DB 문자열 collation 기준; 동률은 ID |
| schedule | 정책 현지 시·분의 숫자 순서 → 주기 → 주간 요일/월간 일자 → ID. 매시간의 분은 00시 기준. 다음 실행 시각이나 시간대 간 UTC 순서가 아님 |

일정은 `분:시[:요일/일자]` 원시 문자열의 사전식 정렬을 쓰지 않는다. UI의 공통 정렬 툴팁으로 의미를 안내한다. 표시값이 번역된 문자열인지와 무관하게 같은 API 계약을 사용한다.

목록 URL을 page/pagesize/sortkey/sortorder의 원천으로 삼는다. 잘못된 URL 정렬은 안전한 기본값으로 정규화하고 유효하지 않은 페이지는 1, 페이지 크기는 현재 기본값으로 복구한다. 검색·정렬·페이지 크기 변경은 첫 페이지로 이동하고 일반 페이지 이동/새로고침/뒤로가기는 정렬과 검색/소유 범위를 보존한다. 서버 count로 마지막 페이지를 계산해 삭제 후 비어 버린 페이지를 보정한다. 클라이언트 비교 함수를 제공하지 않아 응답 순서가 유지된다.

범위·정렬·페이지가 바뀌면 기존 행을 지우고 이전 응답을 버린다. 동일 범위 갱신 실패는 기존 행을 유지하며 공통 오류/재시도 UI를 사용한다. 역할/세션/프로젝트가 달라진 응답은 현재 범위에 적용하지 않는다. 유효하지 않은 정렬을 다른 계정 자료 조회의 우회로로 만들지 않는다.

31 GFS2·32 RBD에 각 20개를 넘는 전용 정책을 만들고 자연 예약이 시험 중 실행되지 않도록 중지 상태로 생성한다. 각 허용 키의 양방향 결과와 count, 다중 페이지의 중복/누락, 동일 값의 안정 순서, 잘못된 키 거부, 소유자 ACL을 독립 SQL과 대조한다. 실제 UI 정렬/검색/페이지 크기/새로고침/URL 복원/마지막 페이지 삭제와 공통 목록 회귀 및 양 테마·반응형을 확인한다. 시험 정책·볼륨·계정을 정상 API로 정리한다. 저장소 임계값 0.90과 기존 운영 자원·dirty FT 작업을 보존한다.

변경 Maven api/server 모듈만 WSL ext4에서 빌드한다. 배포 전 기존 메서드 바이트코드 대조, 허용 클래스 계열만 반영하고 다른 JAR 항목·webapp 서버 디렉터리·설정을 보존한다. UI는 정적 자산만 갱신한다. 전체 Cloud 빌드/Actions dispatch는 수행하지 않는다.
