# SP-07 — 정책 삭제 공통 확인과 대상 보호

대상 #1501 / Epic #1494. 기준 `35f3672cb67`. 가상머신 메뉴의 공통 MoldDialog, 세로 대상 요약, 테마 토큰, 취소→삭제, 반응형 고정 footer와 초점을 따른다.

정책 메뉴와 볼륨 탭은 SnapshotPolicyDeleteDialog 하나를 사용한다. 볼륨 이름/UUID, 정책 UUID, 주기, 저장 일정·시간대·보관 수, 계정·도메인·프로젝트를 최신 API로 읽는다. 삭제 영향과 체크 확인을 표시한다. 삭제는 정책/미래 예약을 제거하며 기존 스냅샷/그 태그·다른 주기 정책은 유지한다. 실행 중 서버의 431 거부는 그대로 따른다.

행 작업은 선택 배열과 구분하여 그 행의 ID/볼륨/주기를 고정한다. 메뉴 경로는 선택 삭제로 확장하지 않는다. SP-11은 같은 identity/read/fingerprint 계약을 재사용할 수 있다. 잘못된 레거시 일정도 삭제할 수 있도록 생성 폼 검증은 적용하지 않는다.

제출 직전 정책과 볼륨 소유/이름/Zone 범위를 다시 읽어 확인 시점의 fingerprint와 비교한다. 변경/실패 시 확인을 해제하고 명시적 재조회 후 다시 확인한다. 경로·대상·사용자·토큰·프로젝트·권한 변경과 늦은 응답은 폐기한다. 삭제 권한뿐 아니라 최신 대상 읽기 권한도 필요하다. 제출 중 확인/닫기/중복 제출은 막는다.

deleteSnapshotPolicies는 동기 API이며 ids에 고정한 UUID 하나를 보낸다. 성공 응답 뒤에도 같은 읽기/소유 범위에서 정책 부재를 확인한다. 네트워크/5xx/응답 불명확 시 원래 대상을 유지하고 결과 확인만 허용하며 자동 재삭제하지 않는다. 목록 부재만으로 삭제와 표시·접근 범위 변화를 구분할 수 없으므로 성공 응답 없는 부재를 삭제 성공으로 판정하지 않는다. 구분 불가 안내를 유지하고 관리자의 결과 확인을 요구한다. 성공 응답을 받은 뒤 검증 조회만 실패한 경우에는 재조회로 완료할 수 있다. 정상 조회에서 남아 있으면 명시적 재조회·재확인을 거쳐 새 시도를 허용한다. 조회 권한/범위를 확인하지 못한 부재는 성공으로 처리하지 않는다. 서버의 최종 ACL·UUID·실행 중 잠금 계약을 유지한다. 실제 비표시 정책의 목록 포함 여부는 배포 API로 관찰하며 숨김으로 추정하지 않는다.

검증은 취소/고정 대상/선택 분리, 변경·삭제·소유/권한·늦은 응답, 중복·실패/불명확 결과 재조회, 네 주기/레거시 데이터, 개인·프로젝트·조회 전용, 31 GFS2/32 RBD 양 UI 경로와 독립 API/DB/스토리지를 포함한다. 실행 중 거부 후 완료·정책 삭제·스냅샷/태그 보존도 확인한다. 라이트/다크×390/768/1280px 및 키보드를 실제 비교하고 시험 자원/dirty FT 작업/설정/WEB-INF를 보존·정리한다. UI만 빌드하며 전체 Cloud 빌드는 수행하지 않는다.

실제 볼륨 탭의 취소에서 BODY로 초점이 떨어진 후보 빌드를 보완했다. Modal의 afterClose까지 자식 컴포넌트를 유지하고, 닫힘을 한 번만 부모에 알린다. 삭제/갱신으로 원래 행이 사라지면 같은 볼륨의 도구 모음으로 초점을 돌리며 범위 전환·폐기 뒤의 콜백은 다른 화면을 바꾸지 않는다. 메뉴는 작업 세대, 볼륨 탭은 정책 UUID로 대화상자 인스턴스를 구분한다.
