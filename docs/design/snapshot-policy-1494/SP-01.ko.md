# SP-01 — 스냅샷 정책 생성창의 볼륨 검색·대상 식별

부모 Epic #1494 / 구현 이슈 #1495. 기준 소스 `b71bb69f28cc53342c55e656742c27d9c6f8f8a5`.

## 문제와 목표

정책 전체 목록의 생성창은 Ant Design Vue 옵션의 `children[0].children`을 검색 텍스트라고 가정한다. 실제 옵션 객체에는 해당 구조가 없어 입력 시 예외가 발생한다. 이름·크기만 표시해 동명 볼륨의 선택 근거도 부족하다.

목표는 API가 현재 호출자에게 반환한 볼륨만 안전하게 검색하고, 표시한 대상과 정책의 실제 volumeid가 일치하도록 하는 것이다. 전체 페이지 조회와 기존 Ready/KVM 적격성 필터를 유지한다.

## 설계

1. 조회·적격성 필터를 통과한 원본 볼륨에서 `value=volume.id`, 이름/크기의 `label`, VM·계정 또는 프로젝트·도메인·Zone·전체 UUID의 `description`, 명시적인 `searchText`를 만든다. 별도 API로 권한 밖 정보를 보충하거나 이름을 식별자로 사용하지 않는다.
2. Select는 공개 `options`/`option` 슬롯을 사용한다. 옵션 본문은 이름·크기와 식별 정보를 두 줄로 보여준다. 선택 후에는 FormSchedule 위에도 식별 정보를 줄바꿈해 표시한다. 선택값은 항상 원래 UUID이다.
3. 검색 함수는 nullable 입력/옵션을 문자열로 정규화하고 공백 정리·대소문자 무시 부분 일치로 검사한다. 이름, 표시/인스턴스 VM 이름, 소유 범위와 UUID를 검색한다. 렌더링 vnode 구조는 읽지 않는다.
4. 로딩/조회 실패 중에는 선택과 정책 제출을 차단하고 기존 오류/재시도를 유지한다. 잘못되거나 지워진 선택은 이전 대상을 남기지 않고 정책 조회 세대를 무효화한다.
5. 기존 `volumeVersion`/`policyVersion`/ownerContext/언마운트 검사를 유지한다. 사용자가 다른 볼륨·프로젝트·로그인 범위로 이동한 뒤 도착한 응답은 새 화면을 채우지 못한다.

## 검증

UI 변경의 표준은 **컴퓨트 > 가상머신** 메뉴이다. 실제 VM 목록/고급 검색/생성 폼과 비교하여 기본 Select의 높이 32px, 글자 14px, 모서리 4px를 유지한다. 세로 레이블, 테마 토큰, 보조 설명과 기본 버튼의 모양은 공통 AntD/MoldDialog 스타일을 사용한다. 추가 식별 정보만 보조 텍스트로 감싸며 공통 VM 스타일을 변경하지 않는다. 동일 화면 폭과 밝은/어두운 테마에서 줄바꿈, 입력/선택 및 하단 작업 버튼 접근성을 확인한다.

- 실제 AntD Select를 장착한 컴포넌트 검사: 정확/부분/대소문자/한글·빈 결과, null/숫자 데이터, 동명이인과 UUID 선택/생성 대상 전달.
- API 페이지 2 이상, Ready/KVM 필터, 조회 실패·재시도, 늦은 목록/정책 응답, 선택 해제·소유 범위 전환의 제어된 응답 검사.
- 31 GFS2·32 RBD에 동일 production UI를 안전하게 배포한 뒤 실제 메뉴의 검색 → 대상 선택 → 정책 생성 → API/DB 확인 → 정상 삭제. 두 환경의 동명 전용 1GiB 볼륨으로 대상 고정을 확인한다.
- 실제 UI의 기존 볼륨 상세 생성 경로, 키보드·좁은 화면·소유 범위 변경을 확인하고 컴포넌트 주입과 실환경 결과를 구분한다.
- 기존 자원 핵심 속성, WEB-INF/config/JAR 및 관리 UI HTTP 200을 보존하고 시험 개체/정책/스토리지 잔여를 정리한다.

## 범위

SP-02 고급 검색, SP-03 매월 일자 검색, SP-04 태그 편집, SP-05 기존 정책 편집 등 다른 하위 항목은 변경하지 않는다. Maven/전체 Cloud/qemu 빌드는 이 UI 변경에 필요하지 않다. UI 집중 검사·lint·production build와 두 클러스터 기능 검증을 각각 기록한다.
