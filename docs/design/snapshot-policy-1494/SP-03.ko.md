# SP-03 — 월 일자 검색의 숫자·표시값 분리

대상 #1497 / Epic #1494. 기준 `a94c23195f4bf31045b79259329dfaa5eb2b4795`.

월 일자 1~28은 숫자 ID로 보존한다. 검색 비교만 문자열로 변환하고 null/없는 옵션은 일치하지 않는 것으로 처리한다. 옵션에 명시적 value=숫자 ID, label=표시 문자열을 부여해 표시 이름 변경이 선택값이나 일정 인코딩을 바꾸지 않게 한다. 시간·시간대·보관 수·태그·편집 UUID와 기존 검증 계약은 유지한다.

기존 공통 FormSchedule과 MoldDialog를 그대로 사용하며 컴퓨트 > 가상머신 표준의 컨트롤·폰트·테마·하단 작업 영역을 따른다. 새로운 스타일·레이아웃을 추가하지 않는다. 스토리지 생성 FormSchedule의 소비자는 RecurringSnapshotVolume(정책 메뉴/볼륨 작업 생성)과 SnapshotPolicyActionDialog(정책 메뉴/볼륨 탭 편집)이다. 컴퓨트 백업의 동명 FormSchedule은 별도 컴포넌트이며 이 변경 대상이 아니다.

실제 AntD Select를 마운트해 1/9/10/28과 29/없는 문자열 검색, 지우기·복구, 숫자/문자 값과 다른 표시 label에서도 숫자 선택값 유지, 매월 1/28일의 제출 schedule을 검사한다. 기존 네 주기·태그·입력/상한·편집·삭제의 집중 검사를 회귀한다.

31 GFS2·32 RBD에서 수정 전 예외와 수정 후 네 소비 경로의 검색·키보드·취소·재열기, 월간 1/28일 생성/편집 요청과 API/독립 DB 일치, 빈 검색 결과 뒤 복구와 초안 보존을 검증한다. API의 잘못된 29일 거부 전후 정책·태그·예약 불변도 확인한다. 라이트/다크×390/768/1280px 및 VM 표준을 실제 대조한다. 시험 전용 볼륨/정책/태그/예약을 정상 API로 정리하고 기존 운영 자원·설정·JAR/PID·WEB-INF·dirty FT 작업을 보존한다. 전역 저장소 임계값은 0.90으로 유지하고 전체 Cloud 빌드는 수행하지 않는다.
