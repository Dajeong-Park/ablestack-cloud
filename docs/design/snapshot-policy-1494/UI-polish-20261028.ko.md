# Breadcrumb 갱신 표시·간격 아이콘과 정책 스냅샷 탭 판정

## 생성 버튼

이전 수정은 목록 행/선택 열/생성 버튼의 배치를 유지했지만 배경 조회 중 생성 버튼을 disabled로 복제해 회색↔파란색 전환이 남았다. 같은 범위의 마지막 성공 목록이 있고 API 권한이 유지되는 동안 신규 생성 시작을 행 작업 준비 상태와 분리한다.

신규 생성은 기존 목록 행을 사용하지 않고 `RecurringSnapshotVolume`에서 볼륨을 새로 조회한다. 현재 정책 목록의 비그룹·비상세 생성 작업, 필요한 API 권한, 같은 목록 범위, 검색/조회 오류 부재를 모두 확인한 경우에만 배경 조회 중 열 수 있다. 편집·삭제·선택 작업, 다른 범위/권한·조회 오류는 기존 guard를 유지한다. 생성창의 볼륨/정책 재조회·입력 검증·실제 제출 권한 검사는 그대로다.

일반 및 선택 행 상태의 갱신 전·중·후에 생성 버튼의 색/테두리/불투명도/좌표가 같은지 확인한다. 요청을 보류한 동안 실제 생성창을 열어 별도 볼륨 조회를 수행하고, 원래 목록 응답이 늦게 돌아와도 선택한 볼륨을 덮지 않는지 확인한다. 이 검사는 저장 없이 취소한다.

## 간격 아이콘

`custom-icon:before`의 고정 검정 글자와 공통 `custom-icon path`의 검정 채움색이 함께 원인이다. 정책 목록 루트의 전용 클래스 안에서 숫자 장식과 SVG path에 currentColor를 적용한다. 공통 VM 색상과 라이트/다크 상속을 사용하고 다른 메뉴 아이콘은 변경하지 않는다.

## 스냅샷 탭 — API 변경 필요, 구현하지 않음

현재 `listSnapshots`는 volumeid/intervaltype/snapshottype·ID·태그 필터가 있지만 정책 UUID 필터가 없고 SnapshotResponse에 생성 정책 UUID도 없다. `includesnapshotcontext=true` 역시 현재 원본 볼륨/VM·복원 사전 검사 정보이며 정책 연결 정보가 아니다.

`listSnapshotPolicies(includepolicycontext=true)`의 latestjob은 보존된 해당 볼륨 job 후보50개 안에서 찾은 최신 일치1건이다. 서버 내부에서는 복호화한 policyid/volumeid를 대조하지만 API에 전체 정책별 job/스냅샷 목록을 반환하지 않는다. 기존 상세의 최근 스냅샷 링크는 정확히 확인된 최신1건이며 전체 목록을 대신하지 않는다.

볼륨+주기로 검색하면 과거 삭제한 정책의 스냅샷과 새 정책의 스냅샷이 섞일 수 있다. 태그는 편집·복사할 수 있으므로 생성 계보를 보증하지 않는다. 정확한 전체 정책 생성 결과를 탭으로 제공하려면 정책 ID 필터와 신뢰할 수 있는 정책–스냅샷 연결/조회·ACL 계약이 필요하다. 사용자 조건에 따라 **탭·API·DB·서버는 변경하지 않는다**. 양쪽 실제 API 계약/응답을 보고서에 기록한다.

## 보존·배포

기존 UI 검토용 클러스터별 볼륨7·정책24·자연 스냅샷1의 ID/주요 정책 필드/중지 상태를 읽기로 확인하고 삭제하지 않는다. UI 정적 파일만 배포하고 WEB-INF/META-INF·설정·JAR/PID·비UI 파일 및 기존 FT 작업을 보존한다. 전체 Cloud/FTCTL 빌드는 실행하지 않는다.
