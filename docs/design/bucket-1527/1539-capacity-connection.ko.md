# #1539 Object Store 용량·연결 상태 및 버킷 대화상자 설계

## 원인과 계약

기존 `storagetotal`은 바이트인데 일반 수정 폼은 GiB 변환과 현재 값 초기화를 하지 않았다. 이름만 수정하는 기존 경로는 용량을 보존했다. 이를 전용 수정 폼으로 교체한다. 수정 요청에는 변경한 필드만 포함한다. size 생략은 유지, 0은 운영자 용량 추적 상한 해제, 양수는 GiB 단위 상한이다. Glue 물리 용량이나 버킷의 무제한 quota를 뜻하지 않는다. 정수 GiB로 나누어지지 않는 기존 바이트는 경고와 원본값을 표시하고 이름 수정 시 보존한다.

기존 total/allocated/reserved의 바이트와 storageused의 KiB API 필드는 각각 유지하고 정확한 십진 문자열 `*bytes` 및 known 플래그를 추가한다. 화면은 BigInt로 계산한다. 미수집을 0으로 표시하지 않는다. 사용량은 관리 버킷의 마지막 성공 수집 시각과 Fresh/Stale/Unknown/Error/NoBuckets 상태를 함께 표시하며 관리 외 Glue 데이터나 실시간 물리 통계로 해석하지 않는다.

## 연결 확인과 실패 복구

`checkObjectStoragePool(id)`는 루트 관리자 전용 POST/no-store API이다. 키나 원문 오류를 반환하거나 기록하지 않고 상태·정규화된 사유·점검 시각·연결 revision만 반환한다. Glue Admin Ops의 서명된 읽기 GET을 사용한다. 네트워크 연결/읽기 제한 각 5초, 전체 deadline 10초, 최대 동시 작업 4개, 재시도와 리다이렉트 없음, 응답 1MiB 제한을 둔다. Connected/AuthFailed/AccessDenied/Unreachable/Unknown을 구분한다. 검증 후 설정이 바뀌면 ConfigurationChanged로 처리한다.

후보 URL/키는 기존 BKT-05 검증 서비스에서 실제 읽기 인증을 확인한 후 동일 트랜잭션으로 저장한다. 실패하면 URL·이름·용량·키가 이전 값을 유지한다. 화면의 실패 상태와 마지막 성공 시각을 별도로 유지하며 재시도할 수 있다. 프로젝트·계정·권한·대상·설정 revision이 바뀐 뒤 도착한 결과는 채택하지 않는다. 기존 키 관리·소속 버킷·삭제 차단 경로를 유지한다.

## 추가 요청: 업로드와 정보 리본

업로드 영역의 배경·본문·파일 목록·버튼에 VM 메뉴와 같은 테마 토큰을 사용한다. 메타데이터는 접근성 라벨이 연결된 키/값/삭제 입력과 64행·2048바이트 제한을 제공한다. 중복 키, 예약 시스템 헤더, 제어 문자, 잘못된 Unicode를 전송 전에 거부한다. 모든 사용자 키는 x-amz-meta- 접두사를 명시하므로 Content-Type 등 시스템 헤더를 덮어쓰지 않는다. 한글 값은 RFC2047로 전송하고 상세는 사람이 읽는 값과 원본 헤더를 구분한다. 부분 성공 후 재시도는 실패한 파일만 전송한다.

보호설정 탭과 버킷 업데이트 대화상자의 리본은 짧은 제목, 설명 문단, 항목명/값 정의 목록, 제약 안내 목록으로 분리한다. 작은 화면에서는 항목을 세로로 전환하고 긴 값은 줄바꿈한다. 할당량 스냅샷도 단위·미확인·추적 해제를 명시한다. 테마별 실제 합성 배경 대비와 컨트롤 접근성을 배포된 화면에서 확인한다.
